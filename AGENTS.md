# Scientific workflow

Read [the verification model](discovery/proof-system.md) before promoting a result. Use the active research branch for scouting, attempts, negative results, independent mathematical challenges and priority searches. Reserve the exact source and quantifiers in a single tracking issue before enrolling a new problem. Reconcile the issue, existing literature, both branches and the certificate index before adding a discovery.

Use the source-linked contracts in discovery/proof-contracts.json. A solver may change its construction or run code in its isolated notebook. Any change to the target, verifier or physical interpretation is a separate reviewed change to the publication branch. Grade submitted data using that branch. Preserve partial theorems with their hypotheses, failed attempts and attribution.

A full witness goes through an independent mathematical challenge, a bounded prior-resolution audit and clean deterministic replay. Publish the exact inputs, checker revision and result. Close the issue only after confirming the deployed certificate. Keep the signed-in hosted model's one-request-per-hour limit; numerical work and Lean checking run separately.
